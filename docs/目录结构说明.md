# 目录结构说明

> 适用基线：`spv8.4` + hajimi 二开。本文只描述当前源码，不再保留早期三层重构时期的失效文件名和行数。

## 一句话架构

项目是一个同时输出油猴脚本和 SillyTavern 扩展的单仓库应用：共享业务代码位于 `src/`，旧 UI 使用原生 DOM/jQuery，新 UI 使用 Vue 3 + Pinia，两者通过 `AutoCardUpdaterAPI` 和 service 层共享能力。

```text
宿主 SillyTavern
  ├─ userscript 入口：src/index.ts
  └─ extension 入口：src/entry-extension.ts
            │
            ▼
  presentation / presentation-v2
            │
            ▼
          service
            │
            ▼
           data
            │
            ▼
          shared
```

依赖原则是 `presentation → service → data → shared`。`presentation-v2` 不应直接依赖旧 `presentation`，Vue 组件也不应绕过 API/Store 直接抓取旧运行时状态。规则由 `scripts/check-arch.mjs` 检查。

## 顶层目录

| 路径 | 用途 | 修改注意事项 |
| --- | --- | --- |
| `src/shared/` | 类型、常量、宿主 API、无业务归属的纯工具 | 不应依赖 data/service/presentation |
| `src/data/` | gateway、repository、SQLite、持久化适配 | 只处理数据与宿主存储，不弹 UI |
| `src/service/` | 表格、AI、Agent、世界书、向量、导入等业务逻辑 | 新功能的核心逻辑优先放这里 |
| `src/presentation/` | 旧 UI、全局 API 装配、启动和 DOM 绑定 | 主要用于兼容，避免继续堆业务算法 |
| `src/presentation-v2/` | Vue 3 + Pinia 新 UI | 页面负责组合，复杂逻辑下沉 composable/store/service |
| `tests/` | Vitest 测试，路径大体镜像源码 | 修复持久化、表格、Agent 时优先补测试 |
| `scripts/` | 构建、产物同步、架构守卫和代码盘点 | 发布前必须运行 build |
| `dist/`、`index.js` | 生成的发布产物 | 禁止手工修改，应由构建覆盖 |

## 入口与构建产物

| 模式 | 源入口 | 产物 |
| --- | --- | --- |
| 油猴脚本 | `src/index.ts` | `dist/index.bundle.js`，并同步到根目录 `index.js` |
| SillyTavern 扩展 | `src/entry-extension.ts` | `dist/extension/index.js` |
| 扩展 + 内嵌助手 | `src/entry-extension-plus-assistantembedded.ts` | 由相应发布流程使用 |

`酒馆助手脚本-SP·数据库.json` 也是生成产物，构建后由 `scripts/sync-userscript-json.mjs` 把最新 bundle 写入 JSON。发生合并冲突时不要手工合并其中的大段脚本文本，应先解决 `src/`，再重新构建生成。

## 业务域索引

| 想修改的功能 | 首选目录 |
| --- | --- |
| 表格更新、回放、持久化、SQL | `src/service/table/`、`src/data/sqlite/` |
| AI 请求、提示词、API 代理 | `src/service/ai/` |
| Agent 和世界书接管 | `src/service/agent/`、`src/service/worldbook/` |
| 剧情任务 | `src/service/plot/`、`src/service/runtime/plot-runtime/` |
| 聊天消息与上下文 | `src/service/chat/`、`src/data/repositories/chat-message-data-repo.ts` |
| 向量索引 | `src/service/vector/`、`src/data/storage/vector-*` |
| 模板助手 | `src/service/template-assistant/` |
| 新 UI 页面 | `src/presentation-v2/pages/` |
| 新 UI 跨页面状态 | `src/presentation-v2/stores/` |
| 新 UI 可复用交互 | `src/presentation-v2/composables/` |
| 对外全局 API | `src/presentation/bootstrap/api-registry.ts` 与 `api-groups/` |

## 开发命令

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm analyze
corepack pnpm typecheck
corepack pnpm test
corepack pnpm build
```

`analyze` 输出各层规模、最大文件和 import 扇出，用来防止新的巨型文件继续增长。`build` 会编译并同步发布产物，同时执行架构守卫。

## 修改约束

1. 只编辑 `src/` 和必要的测试/文档，最后统一构建生成 `dist/`、`index.js` 和 JSON 包装文件。
2. 新业务逻辑不要直接写进 Vue 页面、旧 UI 绑定或 `api-groups`；这些位置只做参数转换和调用编排。
3. 持久化修改必须同时检查 JSON/SQLite 两种路径、快照/回放路径以及删除工作表后的稀疏 `orderNo`。
4. 宿主对象访问集中使用 `shared/host-api` 或 gateway，避免在业务文件新增散落的 `window.parent`、jQuery 和全局变量。
5. 不用“顺手重写”的方式处理大文件。先以测试锁定行为，再按纯函数、状态机、I/O 边界逐段拆分。

更具体的二开入口和重构顺序见 [二开维护指南](./二开维护指南.md)。
